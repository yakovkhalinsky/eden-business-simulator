# Adding a new business simulator

This runbook is for contributors who want to add a new domain to the Eden Business Simulator. Before you start, skim the user-facing documentation for an existing domain (for example [`docs/businesses/cafe.md`](businesses/cafe.md)) and the architecture overview ([`docs/architecture.md`](architecture.md)) to understand how the envelope, clock, and helpers work.

## 1. Create the simulator module

Create a module under `src/eden_business_simulator/businesses/` (for example `healthcare.py`).

## 2. Subclass `BusinessSimulator`

```python
from typing import Any

from eden_business_simulator.businesses.base import BusinessSimulator
from eden_business_simulator.config import SimulatorConfig
from eden_business_simulator.models import Clock


class MySimulator(BusinessSimulator):
    business_type = "my_domain"

    def configure(self, config: SimulatorConfig) -> None: ...
    def initialize(self, seed: int) -> None: ...
    def available_event_types(self) -> list[str]: ...
    def next_event(self, clock: Clock) -> dict[str, Any]: ...
    def state_snapshot(self) -> dict[str, Any]: ...
```

`next_event` must return a dict with at least `event_type` and `payload`. The runner wraps it in an `EventEnvelope` and writes it through the selected output adapter.

## 3. Register the simulator

Import and register the class in `src/eden_business_simulator/businesses/__init__.py`.

## 4. Add tests

Add tests under `tests/` covering:

- initialization,
- the full list of `available_event_types()`,
- that every event type can be emitted under some state,
- determinism with the same seed,
- and any stateful resume behavior.

## 5. Document the new domain

Create a user guide at `docs/businesses/<business_type>.md`. Follow the format of the existing per-business docs:

- slug and source module link,
- domain overview,
- systems represented,
- operational workflow,
- event catalog with one realistic example payload per `available_event_type()`,
- configuration notes,
- CLI quick-start examples.

Update `README.md` to list the new business type and link to its doc.

## Interface contract

```python
class MySimulator(BusinessSimulator):
    business_type = "my_domain"

    def configure(self, config: SimulatorConfig) -> None: ...
    def initialize(self, seed: int) -> None: ...
    def available_event_types(self) -> list[str]: ...
    def next_event(self, clock: Clock) -> dict[str, Any]: ...
    def state_snapshot(self) -> dict[str, Any]: ...
```

## Lifecycle including the optional `restore` hook

For continuous/daemon mode, a simulator may also implement an optional `restore(snapshot: dict[str, Any]) -> None` hook so it can resume deterministic generation from a checkpoint. The default no-op is safe for stateless domains.

`ContinuousRunner` calls `restore` with the `data` field of the snapshot written by `state_snapshot()`. Stateful simulators should restore any counters or entity state that are not regenerated by `initialize(seed)`.

For example, the `gym` simulator restores an invoice counter so that resumed streams do not reuse payment IDs.

```python
def state_snapshot(self) -> dict[str, Any]:
    return {"invoices_counter": self._invoices_counter}

def restore(self, snapshot: dict[str, Any]) -> None:
    self._invoices_counter = snapshot.get("invoices_counter", 0)
```

## Determinism

Use the provided `seed` to initialize `random.Random` and `faker.Faker` instances. Never rely on global random state so that a run is reproducible when given the same seed.

## Framework helpers

The `eden_business_simulator.framework` package contains reusable components so that new business domains do not have to re-implement common patterns from scratch. The `cafe` simulator is the reference implementation (`src/eden_business_simulator/businesses/cafe.py`). See [`docs/architecture.md`](architecture.md) for the conceptual overview of each helper.

| Module | Helper | Purpose |
|--------|--------|---------|
| `framework.ids` | `IdGenerator` | Deterministic IDs such as `ord_0001` per prefix. |
| `framework.actors` | `ActorPool`, `StaffRoster`, `MenuCatalog` | Deterministic entity pools for customers, staff, and menu items with recipes. |
| `framework.inventory` | `RecipeBook`, `InventoryLedger` | Recipe/BOM support, stock receipts, auto-deduction on preparation, wastage, and stock counts. |
| `framework.scheduler` | `DaypartScheduler`, `Daypart` | Vary event weights by simulated clock hour (e.g. breakfast/lunch rushes, close). |
| `framework.state_machine` | `TransitionModel` | Allowed lifecycle transitions for orders, tickets, reservations, etc. |
| `framework.catalog` | `WeightedEventCatalog` | Declarative event weights with state guards and time-of-day modifiers. |

### Example: a minimal simulator using helpers

```python
import random
from typing import Any

from faker import Faker

from eden_business_simulator.businesses.base import BusinessSimulator
from eden_business_simulator.framework.catalog import WeightedEventCatalog
from eden_business_simulator.framework.ids import IdGenerator
from eden_business_simulator.framework.scheduler import DaypartScheduler
from eden_business_simulator.models import Clock


class MySimulator(BusinessSimulator):
    business_type = "my_domain"

    def __init__(self) -> None:
        self.rng = random.Random()
        self.faker = Faker()
        self.id_gen = IdGenerator(self.rng)
        self.catalog = WeightedEventCatalog(self.rng)

    def initialize(self, seed: int) -> None:
        self.rng.seed(seed)
        self.faker.seed_instance(seed)
        self.id_gen = IdGenerator(self.rng)
        self.catalog = WeightedEventCatalog(self.rng)
        self.catalog.register("thing_happened", base_weight=10.0)

    def available_event_types(self) -> list[str]:
        return ["thing_happened"]

    def next_event(self, clock: Clock) -> dict[str, Any]:
        event_type = self.catalog.choose(hour=clock.now.hour, context=self)
        return {
            "event_type": event_type,
            "payload": {
                "thing_id": self.id_gen.next("thing"),
                "at": clock.now.isoformat(),
            },
        }

    def state_snapshot(self) -> dict[str, Any]:
        return {}
```

Use `DaypartScheduler` when event likelihoods should vary by simulated hour, and combine it with `WeightedEventCatalog` by passing the scheduler into the catalog constructor.

## Storage and replay

The simulator ships with a pluggable `StorageAdapter` layer under `src/eden_business_simulator/storage/`:

- `SqliteStorageAdapter` — default local backend (WAL mode, event_log / snapshots / checkpoints tables)
- `NdjsonStorageAdapter` — append-only NDJSON file with companion metadata
- `MemoryStorageAdapter` — volatile in-memory backend for tests

New backends can be added by subclassing `StorageAdapter` and registering them in `src/eden_business_simulator/storage/__init__.py`. Events are persisted with a monotonic `sequence` per `stream_id` and can be replayed through the `replay` CLI command.

If your simulator is intended for long-running daemon use, implement `state_snapshot()` and, if stateful, `restore()` so that `ContinuousRunner` can resume correctly.
